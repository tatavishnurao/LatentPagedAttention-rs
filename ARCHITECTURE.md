# ARCHITECTURE

This file maps the codebase: what each module is for, how data moves between
them, and the invariants each module relies on. If you break one of these
invariants, some check will fail, often far from the code you changed.

For the algebra, precision story and evidence chain told as a narrative, see
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). For commands, see
[docs/REPRODUCIBILITY.md](docs/REPRODUCIBILITY.md).

## Bird's-eye view

The repository is a correctness-first experiment on one question: can a
block-paged cache of small latent rows be written and read directly on the GPU
in place of persistent full K/V rows? It is not a serving runtime. It is built
from four layers, and each layer checks the one below it:

```text
python_ref/   NumPy oracle  ──generates──▶  fixtures/reference/*.json
                                                     │ include_str!
                                                     ▼
crates/plkv-core      scalar Rust CPU reference (tested against fixtures)
                                                     │ called from examples
                                                     ▼
crates/plkv-kernels   cuTile GPU kernels + GPU example harnesses
                      (GPU readback compared with plkv-core output)
                                                     │ driven by
                                                     ▼
scripts/              validation wrappers, timing campaigns, evidence
                      validators  ──write──▶  reports/  (sealed, immutable)
```

The synthetic linear formulation behind every layer:

```text
K_t = L_t W_k,  V_t = L_t W_v                 (L_t = latent row for token t)
score_t = q·K_t / sqrt(D) = (W_k q)·L_t / sqrt(D)       (project query once)
context = Σ_t p_t V_t = (Σ_t p_t L_t) W_v               (aggregate in latent space)
```

Two profiles appear throughout the code:

| profile | Hq | Hkv | group | D (head_dim) | L (latent_dim) | block | max seq | physical blocks | table |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---|
| tiny | 4 | 2 | 2 | 8 | 8 | 2 | 8 | 4 | `[2, 0, 3, 1]` |
| `model_small` | 16 | 4 | 4 | 64 | 32 | 16 | 1024 (P1/C1: up to 131072) | seq/16 | `(17·l + 11) mod B` |

In `model_small`, the persistent cache is 64 B/token for latent
(32 × FP16) and 1024 B/token for full KV (2 × 4 × 64 × FP16). That is the 16×
ratio. It counts persistent cache bytes only.

## Modules

### `python_ref/latent_paged_attention` — the oracle

| module | contents |
|---|---|
| `memory_model.py` | `kv_bytes_per_token_gqa`, `kv_bytes_per_token_latent`, `compression_ratio`, `estimate_total_kv_cache_bytes`. |
| `block_table.py` | `PagedBlockTable`: append-only allocator that hands out physical blocks in order; `logical_blocks_for_seq_len`. |
| `cache_ref.py` | Paged token resolution, K/V and latent single-row writes (they return copies), FP16 storage round-trip and bit patterns. |
| `attention_ref.py` | Stable softmax, paged lookup, and every attention variant in materialized form (rebuild K/V, then attend) and direct form (latent-space), including runtime active-length masking and FP16-storage variants. |
| `fixtures.py` | Builds every JSON fixture deterministically from the functions above. Run it with `scripts/generate_golden_fixtures.sh`. |
| `bench_ref.py`, `cli.py` | CPU timing reference (`small`/`medium` configs) and a Typer CLI for memory estimates. |

Invariants:

- Canonical shapes: `q [batch, Hq, D]`; logical caches `[batch, seq, Hkv, D]`;
  physical caches `[physical_blocks, block_size, width…]`; projections
  `[L, Hkv·D]`, reshaped to `[L, Hkv, D]`.
- GQA mapping is always `kv_head = q_head // group_size`, with
  `q_heads == kv_heads * group_size`. `_validate_group_mapping` enforces this.
- Every attention function raises on non-finite scores, probabilities or
  context, and checks that probability rows sum to 1 within `atol=1e-6`.
- Writes never mutate their input. They return a copy with exactly one row
  replaced. Fixtures depend on this to compare "pre" and "post" caches.
- FP16 storage means "round to IEEE FP16 with NumPy, compute in FP32".
  Overflow to inf raises. This defines bit-exact expectations
  (`*_fp16_bits`).
- In runtime-masked outputs, inactive scores hold the sentinel `-3.4028234663852886e38`
  (`f32::MIN`, not `-inf`), and inactive probabilities are exactly `0.0`.
- Fixtures must be deterministic: tests regenerate them and compare. If you
  change an oracle function, regenerate `fixtures/reference/` in the same
  commit, or the Rust tests that `include_str!` the old JSON will diverge.
- Fixtures also carry GPU-layout copies (`*_gpu_head_major`) next to the
  canonical arrays. The transforms (`_physical_to_gpu_head_major`,
  `_projection_to_gpu_head_major`) are part of the contract with the GPU
  harnesses.

### `crates/plkv-core` — scalar CPU reference

One file, `src/lib.rs`. Public surface:

| group | items |
|---|---|
| errors | `PlkvError` (`ZeroValue`, `ArithmeticOverflow`, `InvalidPagedLookup{reason}`, `TokenOutOfRange`, `TokenNotAllocated`) |
| memory model | `kv_bytes_per_token_gqa`, `kv_bytes_per_token_latent`, `compression_ratio`, `estimate_total_kv_cache_bytes` |
| paging | `BlockTable` (contiguous or append-allocated), `CacheConfig`, `resolve_paged_token_location`, `paged_lookup_f32` |
| writes | `paged_kv_write_f32`, `paged_latent_write_f32`, `paged_latent_write_fp16_storage` |
| FP16 storage | `quantize_f32_to_f16_storage`, `fp16_storage_to_f32` (`half` crate) |
| attention | `contiguous_gqa_decode_f32`, `paged_gqa_decode_f32`, `reconstruct_latent_kv_f32`, `direct_latent_gqa_decode_f32`, `direct_paged_latent_gqa_decode_f32`, `direct_paged_latent_gqa_decode_fp16_storage_f32_accum`, `…_fp16_storage_runtime_f32_accum`, `paged_full_kv_gqa_decode_fp16_storage_runtime_f32_accum` |

All attention functions return `GqaDecodeResult { scores, probabilities, context }`.
These are flat row-major vectors of shape `[Hq, seq]`, `[Hq, seq]` and `[Hq, D]`.

Invariants:

- **Validate, then compute.** Every function rejects zero dimensions, uses
  `checked_mul`/`checked_add` for every size, checks every slice length
  against its declared shape, and range-checks block-table entries before it
  indexes anything. The arithmetic loops then index without bounds checks.
  Add new functions in the same style.
- **Flat layouts (row-major):**
  - latent physical: `[physical_block, block_size, L]`, element
    `(table[t / bs] * bs + t % bs) * L + l`;
  - full-KV physical ("head-major"): `[physical_block, Hkv, block_size, D]`;
  - contiguous K/V: `[Hkv, seq, D]`; reconstructed K/V: `[seq, Hkv·D]`;
  - projections (canonical): `[L, Hkv, D]`, index `(l * Hkv + kv) * D + d`.
    This is **not** the GPU layout (see below).
- Scale is `1 / sqrt(head_dim)`, applied after the dot product.
- Block-table coverage: `table.len() * block_size >= seq_len`. The direct and
  full-KV functions range-check **every** table entry. `paged_gqa_decode_f32`
  and `paged_lookup_f32` check only the covering prefix.
- Runtime variants (`*_runtime_*`) require `1 <= active_seq_len <= max_seq_len`.
  They return `[Hq, max_seq_len]` rows, with `f32::MIN` scores and `0.0`
  probabilities in inactive slots. The latent runtime variant computes the
  active prefix and then pads it, so active values are bit-identical to the
  non-runtime function.
- Finiteness checks differ by function. Most reject non-finite inputs. The
  direct-paged functions check outputs but not the score-row max before
  softmax. `paged_full_kv_gqa_decode_fp16_storage_runtime_f32_accum` checks
  inputs only. Callers in the GPU harnesses still assert finiteness on GPU
  outputs.
- FP16 writes quantize the FP32 replacement first and fail if it overflows,
  so the cache never contains inf or NaN.
- `BlockTable::new` allocates physical blocks monotonically, which makes the
  mapping the identity. Every non-identity mapping used in tests comes from
  fixtures or harness helpers, never from `BlockTable`.
- Unit tests (`#[cfg(test)]`) parse `fixtures/reference/*.json` via
  `include_str!("../../../fixtures/…")`. Moving the fixtures directory breaks
  compilation of the tests. Tolerances are mostly `1e-5`, and `5e-5`/`1e-4`
  for the direct-latent reassociation.

### `crates/plkv-kernels` — cuTile kernels

`src/lib.rs` exposes placeholder `decode`/`paged_cache` modules and, only
with `--features gpu-cutile`, `pub mod cutile`. cuTile is pinned to `=0.2.0`.

Kernel modules (each is a `#[cutile::module]` with `#[cutile::entry]` functions):

| file | profile | purpose |
|---|---|---|
| `paged_lookup.rs` | tiny | gather one physical block per tile block through the table |
| `paged_kv_write.rs` | tiny | single-row K/V write; width-8 lookup |
| `gqa_decode.rs` | tiny | contiguous GQA scores → softmax → context in one kernel |
| `paged_gqa_decode.rs` | tiny | paged full-KV GQA |
| `latent_kv_reconstruction.rs` | tiny | materialize K/V from latent rows |
| `direct_latent_gqa.rs`, `direct_paged_latent_gqa.rs` | tiny | latent-space attention, contiguous and paged (FP32 storage) |
| `paged_latent_write.rs`, `paged_latent_write_fp16.rs` | tiny | single-row latent write, FP32 and FP32→FP16 |
| `direct_paged_latent_gqa_fp16.rs` | tiny | paged latent scores/context from FP16 storage |
| `runtime_sequence.rs` | tiny | active-length-masked scores, softmax, context |
| `model_profile.rs` | model_small | **B0**: latent scores (projection recomputed per block), softmax-1024, serial 64-block context |
| `full_kv_baseline.rs` | model_small | **A0**: FP16 full-KV scores and serial context |
| `model_profile_preprojected.rs` | model_small | **C**: project query once, then score from projected query |
| `p15b_model_profile.rs`, `p15b_full_kv_baseline.rs` | model_small | templates for **B1/A1** (R-TABLE: single-entry table load) |
| `p1_sequence_kernels.rs` | 1K…128K | **generated** A0/B0/C specialised per length |
| `p15b_rtable_kernels.rs` | 1K…128K | **generated** A1/B1 per length |
| `c1.rs` | 1K…8K | **generated** C1 = C with single-entry paging |

Variant naming in examples, scripts and docs: **A** is the full-KV baseline,
**B** is the latent path, **C** is latent with a hoisted query projection.
Suffix **0** means the original whole-table lookup (load the full table tile,
then `extract`). Suffix **1** means the R-TABLE single-entry lookup
`table.load_tile(const_shape![1], [logical])`.

Invariants:

- **Shapes are compile-time constants.** Tile shapes, head counts, the GQA
  divisor (`/ 2i32`, `/ 4i32`), block size (`/ 2i32`, `* 16i32`) and the
  softmax scale (`0.3535533905932738` = 1/√8, `0.125` = 1/√64) are hard-coded
  in each kernel. A kernel only works for its profile. Changing a dimension
  means changing or generating a new kernel, not passing a parameter.
- **The launch grid comes from output partitioning.** The host calls
  `out.partition([1, BLOCK_SIZE])` for scores, which gives grid
  `(Hq, logical_blocks)` with `pid.0 = q_head` and `pid.1 = logical_block`.
  `[1, max_seq]` partitioning for softmax and `[1, D]` for context give a grid
  of `(Hq,)`. Write kernels partition the cache by physical block. A wrong
  partition silently computes the wrong rows.
- **GPU layouts differ from the CPU canonical ones:**
  - projections are uploaded **head-major** `[Hkv, L, D]`, viewed as
    `[Hkv·L, D]`. Tile `(kv_head, 0)` of shape `[L, D]` is that head's slice.
    (Harness helper: `projection_head_major`.)
  - latent cache: `[P·block_size, L]`. Tile `(physical, 0)` of shape
    `[block_size, L]` is one physical block.
  - full-KV cache: `[P·Hkv·block_size, D]`. The tile index is
    `physical * Hkv + kv_head`.
  - block table and `active_seq_len` are device `i32` tensors. Host tables are
    `usize`.
- **Kernels do no bounds checking on table contents.** The host must validate
  the block table before launch (the `plkv-core` reference run does this).
  An out-of-range entry is undefined behaviour on the device.
- **Masking contract:** score kernels write `-3.4028235e38` (not `-inf`) for
  token indices `>= active_seq_len`. Softmax recomputes the mask, subtracts
  the row max and **selects** zero numerators for inactive slots instead of
  relying on `exp` underflow. With `active_seq_len >= 1` the denominator is
  never zero.
- **Context kernels read every logical block**, including inactive ones and
  the unused tail of a partial block, and rely on two things: inactive
  probabilities are exactly `0.0`, and every stored cache value is finite
  (`0 × NaN = NaN`). Unused cache slots must therefore be zero or another
  finite value.
- **Precision:** persistent storage is FP16. `convert_tile` widens to FP32
  before any arithmetic. Projections, query, scores, softmax and context are
  FP32. The FP16 write kernel narrows the FP32 replacement on the device.
- **Write kernels** run one tile block per physical block. Each block loads
  its whole tile, `select`s the replacement row if it owns the target block,
  and stores the whole tile back. Only one token write per launch is
  supported, and concurrent writers to the same cache would race.
- **Write→attention handoff:** the attention launch consumes the device tensor
  returned by the write launch, with no host round-trip. The harnesses read
  the cache back only to check it.
- **A0/B0 are frozen controls.** `validate_rtable_structure.py` (run in CI)
  checks that every generated A0/B0 module still uses the whole-table pattern,
  and that every A1/B1 module uses only singleton table loads, has no
  `extract(table_tile`, and still routes through `physical_block(table, logical_block)`.
- **Generated files must not be edited by hand.** `p1_sequence_kernels.rs`,
  `p15b_rtable_kernels.rs` and `examples/p1_seq_*.rs` come from
  `scripts/generate_p1_sequence_sources.py`, which does textual substitution
  of `1024`/`64` and kernel names in the templates above. `c1.rs` comes from
  `scripts/generate_c1.py`, and `tests/test_c1.py` asserts that the file
  equals the generator's output byte for byte. Edit the template or the
  generator, then regenerate. The substitution is literal, so a stray `1024`
  or `[64]` in a template changes meaning per length.

### `crates/plkv-kernels/examples` — GPU harnesses

Each example is a stage of the validation chain or a timing harness. They
share a structure:

1. Build deterministic inputs (`deterministic_values`, fixtures, or a seeded
   RNG), place logical blocks into physical positions through the table, and
   quantize to FP16 with `plkv_core::quantize_f32_to_f16_storage`.
2. Compute the CPU reference with the matching `plkv_core` function.
3. Upload, launch the kernels in order (score → softmax → context, optionally
   write first), and read back.
4. Assert tolerances, finiteness, row sums, zero inactive probabilities and
   negative controls (identity table must give different scores; changed
   element must change; for C1, a changed query must change the projection).
5. Print `KEY=VALUE` lines, which the `scripts/run_gpu_*.sh` wrappers grep for.

| example | stage |
|---|---|
| `cutile_smoke`, `paged_lookup_gpu`, `paged_kv_write_gpu` | toolchain and paging primitives |
| `gqa_decode_gpu`, `paged_gqa_decode_gpu` | full-KV attention, contiguous and paged |
| `latent_kv_reconstruction_gpu`, `direct_latent_gqa_gpu`, `direct_paged_latent_gqa_gpu` | latent algebra |
| `paged_latent_write_attention_gpu`, `…_fp16_gpu` | write-to-attention, FP32 and FP16 storage |
| `runtime_sequence_gpu` | tiny active lengths `{1,3,4,7,8}` |
| `model_profile_gpu`, `fp16_full_kv_baseline_gpu` | `model_small` latent path and full-KV baseline |
| `p0_gpu_baseline`, `p1_seq_*` | CUDA-event timing of A0/B0/C (P0/P1) |
| `p15_kernel_scaling`, `p15b_rtable` | per-kernel scaling diagnosis and R-TABLE A1/B1 |
| `c1_rtable` | A1/B1/C1 with rotating order, oracle dump for the FP64 checker |

Invariants:

- Every example body sits in `#[cfg(feature = "gpu-cutile")] mod gpu_impl`
  with an empty `main` otherwise, so `cargo test/clippy --workspace
  --all-targets` builds on CPU-only machines. New examples must follow this
  pattern. The `[[example]]` entries in `Cargo.toml` with `required-features`
  cover only the older harnesses.
- Tolerances live in the harness, for example `model_profile_gpu`: scores
  `5e-3`, probabilities `2e-4`, context `2e-3`, row-sum `1e-4`. Changing them
  is a methodology change, not a refactor (see
  `docs/05_no_fake_claims_policy.md`).
- Timing harnesses keep inputs and outputs resident, bracket launches with
  CUDA events on one explicit stream, and exclude JIT, correctness checks and
  readback from timed spans.

Invariants:

  `RELEASE_VALIDATION_OK=1`, and CI greps for those exact lines. Its steps run

  `docs/C1_PROTOCOL.md`) that was fixed before measurement. Each run creates

  which holds because 17 is coprime with every block count used.

  as failures.

## End-to-end data flow (model_small latent decode)

```text
host: deterministic logical latents [seq, 32] FP32
  │  logical_to_physical_latent(table)            table[l] = (17l+11) mod B
  ▼
physical latents [B·16, 32] ── quantize_f32_to_f16_storage ──▶ FP16 (bit-exact)
  │ upload (+ table i32[B], active_seq_len i32[1], Q [16,64], Wk/Wv head-major [4·32,64])
  ▼
(optional) write kernel: FP32 row → FP16 at (table[t/16], t%16)       grid = physical blocks
  ▼
score kernel          grid (16 heads × B logical blocks)
  B0/B1:  per block: projected = Wk[kv]·q   (recomputed per block)
  C/C1:   projection kernel once per head → projected [16,32]; score reads it
  scores[h, 16l..16l+16] = FP32(L_phys[table[l]]) · projected × 0.125, masked → f32::MIN
  ▼
softmax kernel        grid (16 heads): masked max, exp, select-zero, normalize
  ▼
context kernel        grid (16 heads): Σ over all B blocks of p·FP32(L_phys) → [32]
                      then × Wv[kv] → [64]
  ▼
readback → compare with plkv_core::…_runtime_f32_accum (+ FP64 oracle for C1)
```

The full-KV baseline (A0/A1) follows the same path, but stores projected
K and V as FP16 `[B·4·16, 64]`. The score and context kernels index
`physical·4 + kv_head` and skip both projections.

## Cross-cutting invariants (summary)

1. Logical order and physical block order are never assumed to be equal. All
   validation uses non-identity tables, and harnesses include an identity-table
   negative control.
2. The Python oracle produces the fixtures, the fixtures check Rust CPU, and
   Rust CPU checks the GPU. A change to any layer's semantics has to be
   propagated down the chain in the same change.
3. Persistent cache storage is FP16. All arithmetic is FP32 (the C1 oracle
   uses FP64). FP16 conversions must be finite.
4. Inactive positions get the score sentinel `f32::MIN` and probability
   exactly `0`. Cache slots that are stored but unused must be finite.
5. Kernel dimensions are compile-time constants. Code generators, not edits,
   produce per-length variants. A0/B0 stay unchanged as controls.
6. Evidence is append-only, checksummed and tied to its source. Timing claims
   are bounded by the measured boundary (whole process versus CUDA-event
   pipeline versus component).
